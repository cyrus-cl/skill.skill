# PRD Writing Workflow

> 从 PRD 写作对话中抽取稳定的文档结构、个人文风、禁用表达和验收口径，生成可复用的 PRD skill 草稿。

## 适用场景
- 需要反复校准 PRD 结构、语气和验收口径的产品文档任务
- 希望把个人 PRD 写作顺序、禁用表达和范围定义固化下来
- 需要长期统一需求文档的编号、范围边界和风险章节

## 不适用场景
- 只写一次性的活动方案或脑暴提纲
- 没有明确输入材料的空白 PRD 请求
- 仍在频繁改变核心文档结构的探索阶段
- 只想保存某个措辞，而不是完整文档工作流
- 强依赖本次业务背景且不可迁移的临时说明

## 输入要求
- 当前任务的 transcript 或本次对话摘要
- 与任务相关的输入材料或目标输出对象
- 如需合并，额外提供已有 skill Markdown 文件

## 通用层规则（所有同类任务通用）
- 不要从行业背景写起
- 每个模块都用数字编号，范围里必须分 in scope 和 out of scope
- 风险和依赖要单列，不要藏在正文里
- 所有关键指标都要标来源或假设依据

## 个人层规则（你的专属工作习惯）
- 文风偏好：文风保持简洁、专业、少形容词
- 结构偏好：我的 PRD 永远先写目标、用户问题、范围、验收
- 禁用表达：禁用“赋能”“抓手”“闭环”
- 严谨程度：未明确提取
- 其他个人习惯：未明确提取

## 必做步骤
1. 先收敛目标、用户问题、范围和验收标准。
2. 把范围拆成 in scope 与 out of scope。
3. 单列风险、依赖和关键指标来源。
4. 按既定文风和禁用表达清理整篇文档。
5. 为关键判断补上来源、证据或假设说明。
