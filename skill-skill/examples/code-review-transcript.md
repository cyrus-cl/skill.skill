# 代码审查对话转录

## 第1轮
### 用户
帮我 review 一个 Python PR，重点看会不会引入行为变化。

### 助手
我先整体看一下代码风格和目录结构。

## 第2轮
### 用户
不要先说命名风格，先找行为风险和回归风险。

### 助手
好，我先按行为风险来审查。

## 第3轮
### 用户
结论按严重级别排序，先 blocking 再 non-blocking。每条意见都要写影响和建议。

### 助手
明白，我会按严重级别排序，并补影响和建议。

## 第4轮
### 用户
我做 review 时会特别看测试缺口、异常处理和数据库事务边界。

### 助手
收到，我会重点看这三块。

## 第5轮
### 用户
提交信息也一起给建议，统一用 Conventional Commits，scope 必写。

### 助手
好，我会附上提交信息建议。

## 第6轮
### 用户
不要写成长篇教学文章，短句、直接、可执行。

### 助手
明白，输出我会更短、更直接。

## 第7轮
### 用户
这次先忽略 UI 文案，因为这个 PR 只改后端；这是本次特例，以后默认还是正常检查范围。

### 助手
收到，这一条只作为本次例外处理。

## 第8轮
### 用户
现在这套审查口径稳定了，以后类似 Python PR 都按这个来。

### 助手
明白，这已经可以沉淀为稳定的代码审查工作流。
