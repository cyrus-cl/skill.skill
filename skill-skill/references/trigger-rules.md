# trigger-rules

## 一、正向触发信号

以下信号越多，越适合建议蒸馏：

### 1. 连续 2 轮以上同类纠偏

定义：
用户对同一类问题反复校准，例如都在改结构、改评审重点、改文风或改格式。

例子：

- 第2轮要求“按固定维度写竞品分析”，第4轮再次要求“所有竞品都按同一维度展开”。
- 第3轮要求“代码审查先讲风险”，第5轮再次要求“不要先讲格式问题，先讲行为风险”。

### 2. 输出约束连续 3 轮无重大变化

定义：
最近 3 轮里，核心结构和输出要求保持一致，只是补细节或修字句。

例子：

- 第4轮提出“PRD 先目标、再范围、再验收”，第5轮和第6轮仍沿用同一顺序，只补了禁用词和语气。

### 3. 明确出现个人偏好

定义：
用户暴露出自己一贯的口径、文风、结构习惯或禁用表达。

例子：

- “我习惯先给结论，再给论据。”
- “不要写‘赋能’和‘抓手’。”
- “提交信息统一用 `fix(api): ...` 这种格式。”

### 4. 任务已经进入收尾阶段

定义：
用户不再持续推翻前面的规则，而是在做最后确认。

例子：

- “现在这个结构对了，帮我再统一一下措辞。”
- “这版可以了，后面都按这个方式来。”

### 5. 用户明确表达沉淀意图

例子：

- “帮我保存这个流程。”
- “以后按这个来。”
- “能不能沉淀成一个 skill？”

## 二、负向禁止信号

出现以下任一项，都不应主动建议蒸馏：

### 1. 规则还在剧烈变化

例子：

- 第3轮要求表格输出，第4轮又改成长文，第5轮又改回清单。

### 2. 内容明显是一次性上下文

例子：

- “这次只针对 A 客户，不要写其他行业。”
- “今天先不写风险，老板只看摘要。”

### 3. 用户明确表示不想被提醒

例子：

- “先别提保存流程，先把这次做完。”

### 4. 没有足够证据

例子：

- 只有 1 次纠偏，或 transcript 只有 2 轮。

### 5. 目标不是工作流，而是零散句式

例子：

- 用户只是说“以后别用感叹号”，没有其他结构化规则。

## 三、阈值配置

以下阈值用于脚本评分与人工判断：

- `same_pattern_corrections >= 2`
  至少两轮同类纠偏，才说明不是偶发意见。
- `stable_round_window = 3`
  最近三轮核心输出约束无重大变化，才视为基本稳定。
- `min_personal_rules = 1`
  至少识别到一条个人规则，才说明这不是纯公共模板。
- `min_transferable_rules = 3`
  至少三条规则能迁移到未来类似任务，才值得沉淀。
- `one_off_ratio < 0.35`
  一次性特例占比过高时，不建议生成 skill 草稿。
- `explicit_rejection_cooldown = current_session`
  如果用户本次会话明确拒绝过提醒，本次不再主动提议。
