# product-principles

以下原则按优先级排序。每条原则都必须能被执行，不允许停留在口号层面。

## 1. 少打扰原则

定义：
宁愿错过一次蒸馏机会，也不因为一次多余提醒打断用户主任务。

判断标准：

- 如果用户仍在继续改输出，不建议蒸馏。
- 如果同类纠偏少于 2 轮，不建议蒸馏。
- 如果最近 3 轮约束仍明显波动，不建议蒸馏。
- 如果用户拒绝过类似建议，本次会话不再次主动提醒。

## 2. 可解释原则

定义：
所有建议都必须说明依据了对话中的哪部分内容。

判断标准：

- 每条提取规则都要带轮次来源。
- 每个“为什么建议创建 skill”的结论，都必须指向具体纠偏证据。
- 如果无法说清某条规则从哪里来，这条规则不进入最终草稿。

## 3. 先识别后生成

定义：
先判断当前对话是否值得蒸馏，再开始生成候选 skill。

判断标准：

- 先计算重复性、稳定性和可迁移性，再决定是否渲染 skill 草稿。
- 评分不足时，只给出“不建议蒸馏”的结果，不强行生成 skill。
- 生成动作必须晚于识别动作，不能颠倒顺序。

## 4. 先确认后固化

定义：
所有规则都要经过用户确认，才能成为最终 skill。

判断标准：

- 系统只能生成候选草稿，不能直接宣称“已创建最终 skill”。
- 必须允许用户删除误提取规则和临时信息。
- 用户未确认前，不把候选结果视作稳定资产。

## 5. 个人资产优先

定义：
优先保留用户的个人偏好和工作习惯，而不是只保留通用流程。

判断标准：

- 候选结果里必须单独保留 `personal_rules`。
- 输出模板必须显式包含“个人层规则”。
- 如果只能二选一，优先保留用户的个人口径、风格和禁用表达。

## 6. 单一职责原则

定义：
一个 skill 只解决一类任务，不混装多个松散能力。

判断标准：

- 如果候选规则同时覆盖 PRD 写作和代码审查，应建议拆分。
- skill 名称必须能准确描述一类完整工作流。
- 如果大多数规则彼此不共享输入、步骤和输出规范，说明粒度过大，应拆开。
