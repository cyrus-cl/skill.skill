# AGENTS.md

本仓库提供一个 repo-local skill：`skill-skill`。它只用于把当前会话里已经稳定下来的工作流蒸馏为可复用的 skill 草稿，不负责替用户决定规则，不负责跨会话记忆。

它解决的问题不是“把 prompt 写得更强”，而是“把高频重复的纠错、补规则、统一格式和个人方法沉淀为长期可复用能力”。

## 什么时候应该建议调用 `skill-skill`

- 当前任务已经接近完成，用户不再持续修改输出细节。
- 当前会话里出现了至少 2 轮同类纠偏，例如反复修正文档结构、代码审查重点、输出格式或口径。
- 输出约束已经连续 3 轮没有重大变化，只是在补充证据、润色表述或确认细节。
- 用户明确表达过“以后按这个来”“下次也这么做”“帮我沉淀为 skill”“保存这个流程”等意图。

## 什么时候绝对不应该建议调用

- 用户仍在快速试错，规则还在频繁变化。
- 纠偏只有 1 次，尚不足以证明这是可复用工作流。
- 当前要求明显是一次性上下文，例如某个客户、某次会议、某个临时版本、某个当天限定任务。
- 用户刚刚明确拒绝过类似建议，或表示不希望被额外提醒。
- 任务本身还没有收束，继续提醒会打断用户的主线工作。
- 没有可追溯的输入材料，既没有当前对话上下文，也没有用户显式提供的 transcript 或本地文件。

## 建议话术

标准话术必须使用以下句式，不额外加压，不渲染收益，不替用户做决定：

> 我注意到这段对话形成了一套稳定的工作规则，是否需要帮你沉淀为可复用的 skill，下次直接调用？

## 语气要求

- 保持克制、简短、一次一句。
- 只做建议，不暗示“现在就该创建”。
- 先尊重当前任务节奏，再提出是否沉淀。
- 如果用户没有响应，不重复追问。

## 强制守门规则

- 未经用户明确确认，永远不要执行任何实际蒸馏操作。
- 未经用户明确提供，不要读取任何历史会话、外部资料或跨会话上下文。
- 所有“自动建议”都只能发生在当前会话内，且仅是建议，不是后台触发。
- 如果当前工作流还在探索期，宁可错过这一次，也不要为了“多创建一个 skill”去打断用户。
